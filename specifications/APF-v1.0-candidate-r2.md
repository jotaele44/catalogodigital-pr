# APF v1.0 candidate — revision 2 (not certified)

This addendum extends the unchanged predecessor `APF-v1.0.md`. The project remains an independent Puerto Rico data catalog: Spanish primary, English secondary, data-first public presentation and source-first discovery. No mandatory federation dependencies. Index metadata and direct access before selective physical preservation. This is a contract-validation prototype, not authorization for production implementation or publication.

## Identity and ownership
The canonical `collection` type resolves the two previously dangling view owners. `institutional_universe` and `publication_protocol` are additional canonical types; the existing 70 codes remain unchanged. `institution`, `organizational_unit` and `program` support source-entity details and multiple institutional roles. Publisher, authority and custodian remain views/roles, not duplicate entities. Typed relationship rules constrain ownership and cycles. Dataset/document works, versions, distributions, shared digital assets and access endpoints are separate. Each version/distribution has at most one canonical parent; candidate incompleteness is permitted. Supersession requires the same work and acyclic lineage. Minimum cardinalities, full lifecycle enforcement, relationship history and adjudicated identity merging remain open.

## Institutional universe
Fourteen candidate institutional domains define discovery scope, not enumerated publishers. Closed and open universes are separate. A denominator snapshot stores a declared scope, optional count and source-receipt identity, with unique member dispositions. Unknown and zero denominators are nonmeasurable; open universes cannot claim exhaustion. A count match is not proof of exact source membership, and a receipt object is not proof of source bytes. No snapshot or institution is promoted by this prototype. The future immutable source-native membership manifest must reconcile external identifiers before institutional coverage certification.

## Distribution and access
File format, publication protocol, directness, scope, authorization, stability and verification are separate. RESTRICTED is an authorization state rather than a directness class; physical holdings are not online URLs. Legacy migration requires explicit semantic mapping, not guessed numeric equivalence. Access records remain PENDING, and the verified publication function always returns false. Candidate URL checks reject malformed URLs and several credential patterns; they do not constitute network/SSRF qualification or complete secret detection. The 19 baseline metadata fields now have draft Spanish definitions; field-level schemas, rights semantics, full taxonomy translations and scientific applicability remain open.

## Storage and execution
One SQLite prototype with foreign keys, controlled object and access vocabularies, typed relations, institutional universe tables and schema drift checks. This is not a migration of any deployed database: existing unknown schemas are rejected without mutation. The schema digest detects ordinary drift but is not an authenticated tamper-proof ledger. No persistent job supervisor is installed. Execution state, immutable receipts, idempotency and durable recovery must be designed and independently tested before AFK certification. No ingestion or external data download was performed.

## Qualification
The fifteen protocol families are structural reference cases, not implemented acquisition adapters. Local synthetic tests validate candidate contracts only; live protocol qualification is 0/15. The 30-component crosswalk is `reports/apf-crosswalk.json`; the single gate inventory remains `reports/gates.json`. All gates are fail-closed. Source-native verification, security, performance, full specialized contracts, remote CI and durability remain open. APF v1.0 certification and production publication are withheld.
